## Build prompt for Claude Code

```text
You are Claude Code, acting as lead engineer on the Veltrix Operations Optimization Platform monorepo.
Before writing code, read CLAUDE.md, the PRD sections listed below in docs/prd/, docs/adr/ and docs/data-dictionary/. Restate the task in 5 to 10 bullets, list assumptions and open questions, propose a file-level plan, then write the acceptance tests first.

TASK P5-02: Production engine with CP-SAT
PRD: §12, §16   Requirements: PRD01, PRD02   Depends on: P5-01, P4-02

CONTEXT
PRD01: no overlaps, no incompatible lines, no unavailable materials. PRD02: a different sequence changes timing and cost. Implement exactly the signed formulation in docs/engines/production/formulation.md.

BUILD
1. Model builder from the input snapshot with time discretization from the run profile.
2. Optional interval per operation and eligible line; exactly one presence literal per scheduled operation; unscheduled literal with penalty when deferral is allowed.
3. NoOverlap per resource and sequence-dependent changeovers via AddCircuit with transition times.
4. Precedence with transfer time, downtime as fixed intervals, batch size bounds.
5. Material availability with reservoir constraints using confirmed receipts and release times.
6. Lateness variables, locks and frozen window as fixed values, authorized overtime windows.
7. Lexicographic objectives by sequential solves that fix earlier objective bounds; weighted mode per configuration.
8. Solution hints from the previous plan for stability; solver parameters (workers, seed, time limit) from the run profile.
9. Extraction to the plan schema with per-operation line, start, end, quantity and reasons for unscheduled orders.

NON-NEGOTIABLES
- Engine code never imports packages/validators.
- Split and interruption are explicit configuration, never defaults (§12).
- Status reporting through the P4-02 mapper only.
- Organization scope comes from the session or API key only; permissions are enforced on the server; every mutating action writes an audit event.
- No secrets or personal data in code, fixtures, logs or messages. User-facing text exists in Arabic and English.

ACCEPTANCE (automated tests; name requirement tests test_<REQ-ID>_<behaviour>)
- All tiny cases reach the enumerated optimum and report proven optimal.
- The P5-03 validator finds zero hard violations on every reference output (test_PRD01_*).
- Swapping a sequence changes changeover time and cost (test_PRD02_*).
- Benchmarks recorded for small, medium and large.

OUT OF SCOPE
Replanning (P5-05), explanations (P8-01).

HANDOFF
Work on branch feat/p5-02-production-engine-with-cp-sat. Run make lint, make typecheck and make test.
```
