```text
TASK P0-05: Reference case library and synthetic data generator
PRD: §27, §34   Requirements: -   Depends on: P0-04

CONTEXT
PRD §27 starts model testing with small cases whose solutions are known or can be enumerated, then representative data and boundary cases. §34 requires clearly labeled synthetic data during development.

BUILD
1. tests/reference-cases/production/{tiny,small,medium,large}/ as JSON files that follow the data dictionary.
2. A seeded generator in packages/contracts/synth producing orders, routings, lines, compatibility, changeover matrices, calendars, downtime and material receipts; every record carries synthetic: true and a dataset label.
3. A brute-force enumerator for tiny cases (up to 6 operations and 2 lines) that computes the true optimum for lateness, changeover time and cost objectives, with results stored next to each case.
4. Edge cases: demand above capacity, missing material, impossible due window, line incompatibility, locked operation conflict, empty calendar.
5. README per folder describing each case and its expected outcome.

NON-NEGOTIABLES
- No real customer data.
- Same seed must give byte-identical output.
- The enumerator must not import anything from packages/engines.
- Organization scope comes from the session or API key only; permissions are enforced on the server; every mutating action writes an audit event.
- No secrets or personal data in code, fixtures, logs or messages. User-facing text exists in Arabic and English.

ACCEPTANCE (automated tests; name requirement tests test_<REQ-ID>_<behaviour>)
- At least 25 tiny cases and 10 edge cases committed.
- Generator determinism test (hash comparison) passes.
- Enumerator results checked in and reproducible.

OUT OF SCOPE
Transportation and inventory cases (added in P13 and P14).

HANDOFF
Work on branch feat/p0-05-reference-case-library-and-synthetic. Run make lint, make typecheck and make test. Open a PR whose description contains: summary, design decisions, a traceability table (task, PRD section, requirement id, test name), commands run with results, known limitations, and questions for the reviewer. Do not report the task as done if any acceptance test is missing, skipped or failing.
```
