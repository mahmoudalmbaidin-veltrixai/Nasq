TASK P5-06: Production results, indicators and reasons
PRD: §12, §20   Requirements: KPI01   Depends on: P5-02

CONTEXT
§12 outputs: a timeline filterable by line, product and order, operation lists, quantities, utilization, changeover and overtime hours, late or unscheduled orders with explainable reasons. Distinguish a proven capacity shortage from an estimated explanation.

BUILD
1. Result APIs: timeline by line, product and order; operations list; quantities.
2. Indicators: utilization with denominator = available hours from the calendar; changeover hours; overtime hours; lateness.
3. Late and unscheduled orders with reasons classified as proven (validator or infeasibility evidence) or estimated (needs verification).
4. Filters and export hooks for reports (P9-03).

NON-NEGOTIABLES
- No reason without an evidence link to inputs or validation results.
- Organization scope comes from the session or API key only; permissions are enforced on the server; every mutating action writes an audit event.
- No secrets or personal data in code, fixtures, logs or messages. User-facing text exists in Arabic and English.

ACCEPTANCE (automated tests; name requirement tests test_<REQ-ID>_<behaviour>)
- Utilization formula documented and unit-tested.
- Every reason carries its classification.
- Filters return consistent totals.

OUT OF SCOPE
Gantt screen (P10-05).

HANDOFF
Work on branch feat/p5-06-production-results-indicators-and-reasons. Run make lint, make typecheck and make test. Open a PR whose description contains: summary, design decisions, a traceability table (task, PRD section, requirement id, test name), commands run with results, known limitations, and questions for the reviewer. Do not report the task as done if any acceptance test is missing, skipped or failing.
