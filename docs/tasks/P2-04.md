## Build prompt for Claude Code

```text
You are Claude Code, acting as lead engineer on the Veltrix Operations Optimization Platform monorepo.
Before writing code, read CLAUDE.md, the PRD sections listed below in docs/prd/, docs/adr/ and docs/data-dictionary/. Restate the task in 5 to 10 bullets, list assumptions and open questions, propose a file-level plan, then write the acceptance tests first.

TASK P2-04: Import pipeline: staging, mapping, preview, publish
PRD: §10   Requirements: DAT01, DAT02   Depends on: P2-01, P2-03

CONTEXT
§10: upload to staging, map columns, validate, preview differences, publish an accepted version. A failed file must not change published data. Support insert or update by stable external id; never infer deletion from absence in a partial file.

BUILD
1. Upload CSV and XLSX into per-job staging tables; store the original file privately.
2. Column mapping contract and saved mapping templates per source.
3. Validation stage that calls the rule library from P2-05.
4. Difference preview: inserts, field-level updates and deactivations listed explicitly. Full-snapshot mode is an explicit choice that shows its deactivations before publish.
5. Publish in a single transaction that creates a new published data version.
6. Upsert by stable external id so the same file imported twice is a no-op.
7. Import job states (uploaded, mapped, validated, previewed, published, failed) with audit events.

NON-NEGOTIABLES
- Blocking errors prevent publish.
- Warnings can be accepted only with a documented reason and actor.
- The source-of-truth matrix decides which fields an import may change.
- Organization scope comes from the session or API key only; permissions are enforced on the server; every mutating action writes an audit event.
- No secrets or personal data in code, fixtures, logs or messages. User-facing text exists in Arabic and English.

ACCEPTANCE (automated tests; name requirement tests test_<REQ-ID>_<behaviour>)
- A failing file leaves the published version unchanged (test_DAT01_*).
- Importing the same orders twice does not duplicate them (test_DAT02_*).
- A partial file does not deactivate missing records.
- Preview counts equal the published result.

OUT OF SCOPE
ERP connectors (P7-04).

HANDOFF
Work on branch feat/p2-04-import-pipeline-staging-mapping-preview. Run make lint, make typecheck and make test. Open a PR whose description contains: summary, design decisions, a traceability table (task, PRD section, requirement id, test name), commands run with results, known limitations, and questions for the reviewer. Do not report the task as done if any acceptance test is missing, skipped or failing.
```
