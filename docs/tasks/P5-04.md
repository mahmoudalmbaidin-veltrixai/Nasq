## Build prompt for Codex

```text
You are Codex, acting as implementation engineer on the Veltrix Operations Optimization Platform monorepo.
Before writing code, read AGENTS.md, the PRD sections listed below in docs/prd/, docs/adr/ and docs/data-dictionary/. Restate the task in 5 to 10 bullets, list assumptions and open questions, propose a file-level plan, then write the acceptance tests first.

TASK P5-04: Production test and benchmark suite
PRD: §25, §27   Requirements: PRD01, PRD02   Depends on: P5-02, P5-03

CONTEXT
§27: every template needs a reference acceptance set at small, medium and large sizes; examine solution quality, solve-time distribution and memory; changes to the model, solver or rounding require regression tests before deployment.

BUILD
1. Enumerator comparison tests for tiny cases.
2. Hypothesis property tests: random small instances must return an honest status and pass the validator when feasible.
3. Edge-case tests from P0-05 with expected statuses and exceptions.
4. Sensitivity tests: more capacity, changed costs, added locks; check changes are understandable and stable.
5. A benchmark runner recording per case: status, objective, gap, solve time, peak memory; output as JSON and a Markdown report.
6. docs/engines/production/thresholds.yaml and a comparison script that fails on regressions.
7. Fast subset in PR CI and full set nightly.

NON-NEGOTIABLES
- Agents may propose but never change thresholds.
- Organization scope comes from the session or API key only; permissions are enforced on the server; every mutating action writes an audit event.
- No secrets or personal data in code, fixtures, logs or messages. User-facing text exists in Arabic and English.

ACCEPTANCE (automated tests; name requirement tests test_<REQ-ID>_<behaviour>)
- Fast suite runs in under 5 minutes on PRs.
- Nightly run uploads the benchmark report.
- A deliberately degraded engine branch fails the regression check.

OUT OF SCOPE
Load testing (P11-04).

HANDOFF
Work on branch feat/p5-04-production-test-and-benchmark-suite. Run make lint, make typecheck and make test. Open a PR whose description contains: summary, design decisions, a traceability table (task, PRD section, requirement id, test name), commands run with results, known limitations, and questions for the reviewer. Do not report the task as done if any acceptance test is missing, skipped or failing.
```
