```text
TASK P0-04: Data dictionary, source-of-truth matrix and state machines
PRD: §9, §10, §17, §34, §36   Requirements: -   Depends on: P0-01

CONTEXT
PRD §34 requires a data dictionary, source-of-truth matrix, rule versions, solve and plan state definitions and reference cases before scaling. These files become the contract every other task obeys.

BUILD
1. docs/data-dictionary/*.yaml: every entity from §9 with fields, types, units, precision, required flags, effective dating, external identifier rules and the engines that read it.
2. docs/sot-matrix.yaml: for each entity or field, the source of truth (ERP, platform, execution system), editing owner, synchronization direction and default freshness threshold (§10).
3. docs/state-machines/solve.yaml: queued → running → succeeded | time_limit | failed | canceled.
4. docs/state-machines/result-status.yaml: proven_optimal, feasible, proven_infeasible, inconclusive, failed_or_canceled, each with interface behaviour from §16.
5. docs/state-machines/plan.yaml: draft → calculated → in_review → submitted → approved → exported | released → in_progress → completed | superseded, plus rejected; each transition lists guard conditions and allowed roles.
6. A generator in packages/contracts that produces Python enums and TypeScript types from the YAML, run in CI so code cannot drift.
7. docs/glossary.md from PRD §36.

NON-NEGOTIABLES
- Solve states and plan states are separate machines (§17).
- No state name may exist in code that is not in the YAML.
- Organization scope comes from the session or API key only; permissions are enforced on the server; every mutating action writes an audit event.
- No secrets or personal data in code, fixtures, logs or messages. User-facing text exists in Arabic and English.

ACCEPTANCE (automated tests; name requirement tests test_<REQ-ID>_<behaviour>)
- Schema lint validates every YAML file.
- Generated enums compile in Python and TypeScript.
- A transition test enumerates every allowed and every forbidden transition.
- Product owner sign-off recorded in the PR.

OUT OF SCOPE
Database models (P2-01).

HANDOFF
Work on branch feat/p0-04-data-dictionary-source-of-truth. Run make lint, make typecheck and make test. Open a PR whose description contains: summary, design decisions, a traceability table (task, PRD section, requirement id, test name), commands run with results, known limitations, and questions for the reviewer. Do not report the task as done if any acceptance test is missing, skipped or failing.
```
