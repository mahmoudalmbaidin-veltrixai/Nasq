## Build prompt for Claude Code

```text
You are Claude Code, acting as lead engineer on the Veltrix Operations Optimization Platform monorepo.
Before writing code, read CLAUDE.md, the PRD sections listed below in docs/prd/, docs/adr/ and docs/data-dictionary/. Restate the task in 5 to 10 bullets, list assumptions and open questions, propose a file-level plan, then write the acceptance tests first.

TASK P0-01: Repository scaffold and engineering conventions
PRD: §22, §29, §34   Requirements: -   Depends on: -

CONTEXT
Greenfield repository. PRD §22 proposes a modular application: one logical backend, one relational database, long-running calculations in background workers, and a Vue + TypeScript web interface. Dozens of microservices are explicitly not wanted.

BUILD
1. Create the monorepo layout: apps/api (FastAPI), apps/worker, apps/web (Vue 3 + TypeScript + Vite), packages/core, packages/contracts, packages/engines/{production,transportation,inventory}, packages/validators, docs/{prd,adr,tasks,data-dictionary,state-machines,engines,runbooks}, tests/{reference-cases,e2e,security,performance}, infra/.
2. Python 3.12 workspace (uv or Poetry) with ruff, mypy --strict, pytest, pytest-cov, hypothesis and import-linter configured at the root.
3. packages/core with settings (pydantic-settings), UUIDv7 ids, structured JSON logging with request id, a base error type mapped to RFC 7807 problem responses.
4. apps/web with Vue 3, TypeScript strict, Pinia, vue-router, vue-i18n, Vitest, Playwright, ESLint and Prettier.
5. docker-compose for local development: postgres:16, api, worker, web, mailpit, minio. Makefile targets: dev, test, lint, typecheck, migrate, bench.
6. Commit CLAUDE.md and AGENTS.md from the plan at the repository root, a PR template with a traceability table (task id, PRD section, requirement id, test name), and CODEOWNERS routing packages/engines/** to the OR specialist.
7. Health endpoints /healthz (process) and /readyz (database and queue reachable).

NON-NEGOTIABLES
- No feature code in this task.
- Pin every dependency and record its license in docs/adr/licenses.md.
- .env.example contains placeholders only.
- Organization scope comes from the session or API key only; permissions are enforced on the server; every mutating action writes an audit event.
- No secrets or personal data in code, fixtures, logs or messages. User-facing text exists in Arabic and English.

ACCEPTANCE (automated tests; name requirement tests test_<REQ-ID>_<behaviour>)
- `make dev` starts all services on a clean machine and /readyz returns 200.
- `make test` runs at least one passing test in every Python package and in apps/web.
- `make lint` and `make typecheck` pass with zero warnings.
- gitleaks finds no secrets.
- PR template and CODEOWNERS exist.

OUT OF SCOPE
CI workflows (P0-02), authentication, any business feature.

HANDOFF
Work on branch feat/p0-01-repository-scaffold-and-engineering-conventions. Run make lint, make typecheck and make test. Open a PR whose description contains: summary, design decisions, a traceability table (task, PRD section, requirement id, test name), commands run with results, known limitations, and questions for the reviewer. Do not report the task as done if any acceptance test is missing, skipped or failing.
```
