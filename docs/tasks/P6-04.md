## Build prompt for Codex

```text
You are Codex, acting as implementation engineer on the Veltrix Operations Optimization Platform monorepo.
Before writing code, read AGENTS.md, the PRD sections listed below in docs/prd/, docs/adr/ and docs/data-dictionary/. Restate the task in 5 to 10 bullets, list assumptions and open questions, propose a file-level plan, then write the acceptance tests first.

TASK P6-04: Manual edit and revalidation
PRD: §12, §17   Requirements: RUN03   Depends on: P6-01, P5-03

CONTEXT
§12: dragging an operation must trigger validation before saving or approval and prevent hard-constraint violations; a visual move alone does not establish feasibility.

BUILD
1. Edit API accepting moves (operation, line, start), lock and unlock.
2. Runs the validator on the edited plan and returns violations with measured values and limits.
3. Saves a new version only if there are no hard violations; soft violations are shown with their penalty.
4. Optional repair solve that keeps the user's locks.

NON-NEGOTIABLES
- Edits always create a new version.
- Organization scope comes from the session or API key only; permissions are enforced on the server; every mutating action writes an audit event.
- No secrets or personal data in code, fixtures, logs or messages. User-facing text exists in Arabic and English.

ACCEPTANCE (automated tests; name requirement tests test_<REQ-ID>_<behaviour>)
- Move to an incompatible line is rejected.
- Move causing an overlap is rejected.
- Soft lateness is reported with its penalty.

OUT OF SCOPE
Gantt drag interaction (P10-05).

HANDOFF
Work on branch feat/p6-04-manual-edit-and-revalidation. Run make lint, make typecheck and make test. Open a PR whose description contains: summary, design decisions, a traceability table (task, PRD section, requirement id, test name), commands run with results, known limitations, and questions for the reviewer. Do not report the task as done if any acceptance test is missing, skipped or failing.
```
