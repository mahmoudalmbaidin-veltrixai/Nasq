## Build prompt for Claude Code

```text
You are Claude Code, acting as lead engineer on the Veltrix Operations Optimization Platform monorepo.
Before writing code, read CLAUDE.md, the PRD sections listed below in docs/prd/, docs/adr/ and docs/data-dictionary/. Restate the task in 5 to 10 bullets, list assumptions and open questions, propose a file-level plan, then write the acceptance tests first.

TASK P10-01: Frontend foundation, i18n and RTL
PRD: §8   Requirements: -   Depends on: P0-01, P1-02, P1-05

CONTEXT
§8: users see only enabled engines and choose organization, site and period within their permissions; Arabic and English directionality with correct display of identifiers, numbers and dates; every screen has empty, loading and error states and no unlabeled trial numbers.

BUILD
1. App shell, routing, Pinia stores and an API client generated from OpenAPI.
2. Design tokens and base components: data table, form fields, dialog, toast, empty state, loading state, error state mapped from RFC 7807.
3. vue-i18n with Arabic and English, a direction switch on <html>, CSS logical properties only.
4. Bidi isolation for codes, numbers and dates (<bdi>, unicode-bidi: isolate) and locale-aware formatting in the site time zone.
5. Organization, site and period selector; navigation from /me/features so disabled engines never appear.
6. Session handling with MFA and permission-aware routing (cosmetic only).
7. A lint rule that rejects hardcoded user-facing strings.

NON-NEGOTIABLES
- Never compute business numbers in the browser that the server should provide.
- Synthetic data shown in development carries a visible label.
- Organization scope comes from the session or API key only; permissions are enforced on the server; every mutating action writes an audit event.
- No secrets or personal data in code, fixtures, logs or messages. User-facing text exists in Arabic and English.

ACCEPTANCE (automated tests; name requirement tests test_<REQ-ID>_<behaviour>)
- Playwright screenshot tests in Arabic and English for the shell.
- The string lint rule passes.
- Disabled engines do not appear in navigation.

OUT OF SCOPE
Individual screens (P10-02 to P10-06).

HANDOFF
Work on branch feat/p10-01-frontend-foundation-i18n-and-rtl. Run make lint, make typecheck and make test. Open a PR whose description contains: summary, design decisions, a traceability table (task, PRD section, requirement id, test name), commands run with results, known limitations, and questions for the reviewer. Do not report the task as done if any acceptance test is missing, skipped or failing.
```
