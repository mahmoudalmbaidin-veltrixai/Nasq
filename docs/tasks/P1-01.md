## Build prompt for Claude Code

```text
You are Claude Code, acting as lead engineer on the Veltrix Operations Optimization Platform monorepo.
Before writing code, read CLAUDE.md, the PRD sections listed below in docs/prd/, docs/adr/ and docs/data-dictionary/. Restate the task in 5 to 10 bullets, list assumptions and open questions, propose a file-level plan, then write the acceptance tests first.

TASK P1-01: Tenancy and organization isolation
PRD: §6, §9, §23, §24   Requirements: TEN01   Depends on: P0-03, P0-04

CONTEXT
TEN01: a user can never reach a record outside their scope. §24 requires isolation across queries, files, queues, caches, logs, exports and restored backups, with cross-account access tests. §23: a client must not switch organizations by sending a different identifier.

BUILD
1. Tables organizations and sites (code, name, type, currency, IANA time zone) with Alembic migration.
2. Request context that derives org_id only from the authenticated session or API key.
3. A repository base class and SQLAlchemy event hook that add the org filter to every org-owned model; org_id NOT NULL with foreign key and index on every org-owned table.
4. Postgres row-level security on every org-owned table using SET LOCAL app.org_id per transaction; the application database role has no BYPASSRLS.
5. Org-prefixed keys for cache entries, storage objects and queue payloads, and an org_id field on every log line.
6. A cross-tenant test harness: fixtures create organizations A and B; a parametrized test calls every registered route as a user of A using identifiers that belong to B.

NON-NEGOTIABLES
- A missing org filter must fail closed.
- Requests for another organization's ids return 404, not 403, to avoid enumeration.
- Raw SQL in product code is allowed only through a reviewed helper that sets the org context.
- Organization scope comes from the session or API key only; permissions are enforced on the server; every mutating action writes an audit event.
- No secrets or personal data in code, fixtures, logs or messages. User-facing text exists in Arabic and English.

ACCEPTANCE (automated tests; name requirement tests test_<REQ-ID>_<behaviour>)
- The harness covers 100% of routes and fails when a new route is not registered in it.
- Direct SQL using the application role cannot read rows of another organization.
- File, cache and queue keys contain the org prefix (unit tests).
- TEN01 test named test_TEN01_* passes.

OUT OF SCOPE
Role and site permissions (P1-03).

HANDOFF
Work on branch feat/p1-01-tenancy-and-organization-isolation. Run make lint, make typecheck and make test. Open a PR whose description contains: summary, design decisions, a traceability table (task, PRD section, requirement id, test name), commands run with results, known limitations, and questions for the reviewer. Do not report the task as done if any acceptance test is missing, skipped or failing.
```
