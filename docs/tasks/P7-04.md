## Build prompt for Codex

```text
You are Codex, acting as implementation engineer on the Veltrix Operations Optimization Platform monorepo.
Before writing code, read AGENTS.md, the PRD sections listed below in docs/prd/, docs/adr/ and docs/data-dictionary/. Restate the task in 5 to 10 bullets, list assumptions and open questions, propose a file-level plan, then write the acceptance tests first.

TASK P7-04: Public integration API v1
PRD: §23   Requirements: INT01   Depends on: P2-04, P7-01, P7-03

CONTEXT
§23: core interfaces import orders, resources and stock; query solve and plan status; export an approved plan; receive execution events. Document versioning, pagination, time limits and error codes. Credentials are organization- and scope-limited, rotatable and revocable.

BUILD
1. /api/v1 endpoints for import (asynchronous jobs reusing the P2-04 pipeline), solve and plan status, approved plan export and execution events.
2. API keys hashed at rest, scoped to one organization and a list of scopes, rotatable with overlap, revocable.
3. Idempotency-Key header support for all POST creations.
4. Cursor pagination, rate limits per key, RFC 7807 errors with stable codes.
5. OpenAPI documentation with request and response examples.

NON-NEGOTIABLES
- The organization is derived from the key, never from the payload.
- Organization scope comes from the session or API key only; permissions are enforced on the server; every mutating action writes an audit event.
- No secrets or personal data in code, fixtures, logs or messages. User-facing text exists in Arabic and English.

ACCEPTANCE (automated tests; name requirement tests test_<REQ-ID>_<behaviour>)
- A key of organization A cannot reach organization B.
- A revoked key fails immediately.
- Repeating a POST with the same Idempotency-Key returns the original result.

OUT OF SCOPE
Specific ERP connectors per customer (configuration work in the pilot).

HANDOFF
Work on branch feat/p7-04-public-integration-api-v1. Run make lint, make typecheck and make test. Open a PR whose description contains: summary, design decisions, a traceability table (task, PRD section, requirement id, test name), commands run with results, known limitations, and questions for the reviewer. Do not report the task as done if any acceptance test is missing, skipped or failing.
```
