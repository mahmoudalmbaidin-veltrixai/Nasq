TASK P7-03: Execution events
PRD: §9, §18   Requirements: INT01   Depends on: P6-01

CONTEXT
§18: every event has an identifier, occurrence time, receipt time and source; repeated events must not double-count production or shipments; handle out-of-order arrival through a documented policy; corrections create traceable adjustments.

BUILD
1. Events API and manual entry for execution supervisors.
2. Fields: id, occurrence time, receipt time, source, operation, quantity or status, external id.
3. Deduplication by (source, external id).
4. Out-of-order policy: apply by occurrence time and recompute projections; document it in docs/runbooks/events.md.
5. Corrections as adjustment events linked to the original.
6. Operation status projections and a replanning suggestion trigger.

NON-NEGOTIABLES
- Original events are never modified or deleted.
- Organization scope comes from the session or API key only; permissions are enforced on the server; every mutating action writes an audit event.
- No secrets or personal data in code, fixtures, logs or messages. User-facing text exists in Arabic and English.

ACCEPTANCE (automated tests; name requirement tests test_<REQ-ID>_<behaviour>)
- Duplicate event does not double count.
- Late event reorders state correctly.
- Correction keeps the original and links to it.

OUT OF SCOPE
Monitoring screen (P10-06).

HANDOFF
Work on branch feat/p7-03-execution-events. Run make lint, make typecheck and make test. Open a PR whose description contains: summary, design decisions, a traceability table (task, PRD section, requirement id, test name), commands run with results, known limitations, and questions for the reviewer. Do not report the task as done if any acceptance test is missing, skipped or failing.
