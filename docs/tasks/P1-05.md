```text
TASK P1-05: Platform administration and engine entitlements
PRD: §5, §6, §28   Requirements: -   Depends on: P1-03

CONTEXT
§28: the product is sold by engine or bundle with site, resource and concurrent-solve limits; contracts and collection are handled outside the product while entitlement status is recorded. §5: do not show controls for unfinished engines as working features.

BUILD
1. Platform admin API: create organization, suspend, reactivate.
2. Entitlements per organization: enabled engines, maximum sites, maximum resources, maximum concurrent solves, solve time ceiling, contract status.
3. An entitlement service used by API routes and workers.
4. A /me/features endpoint that tells the web app which engines to show.

NON-NEGOTIABLES
- Entitlement changes are audited.
- Platform admin endpoints never return customer operational data.
- Organization scope comes from the session or API key only; permissions are enforced on the server; every mutating action writes an audit event.
- No secrets or personal data in code, fixtures, logs or messages. User-facing text exists in Arabic and English.

ACCEPTANCE (automated tests; name requirement tests test_<REQ-ID>_<behaviour>)
- Calls to a disabled engine return 403 with a clear message.
- Creating a site beyond the limit fails cleanly.
- /me/features reflects entitlements.
- Tests for each.

OUT OF SCOPE
Billing and payments (not required, §28).

HANDOFF
Work on branch feat/p1-05-platform-administration-and-engine-entitlements. Run make lint, make typecheck and make test. Open a PR whose description contains: summary, design decisions, a traceability table (task, PRD section, requirement id, test name), commands run with results, known limitations, and questions for the reviewer. Do not report the task as done if any acceptance test is missing, skipped or failing.
```
