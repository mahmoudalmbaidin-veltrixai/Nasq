```text
You are Codex, acting as implementation engineer on the Veltrix Operations Optimization Platform monorepo.
Before writing code, read AGENTS.md, the PRD sections listed below in docs/prd/, docs/adr/ and docs/data-dictionary/. Restate the task in 5 to 10 bullets, list assumptions and open questions, propose a file-level plan, then write the acceptance tests first.

TASK P2-07: Secure file handling and safe exports
PRD: §21, §22, §24   Requirements: -   Depends on: P1-03

CONTEXT
§24: validate and limit uploaded files, keep them outside public access, and prevent user values from becoming executable spreadsheet formulas. §21: recheck authorization at download time even for a saved link.

BUILD
1. A storage service with org-prefixed keys in a private bucket.
2. Upload limits by size and type, MIME sniffing, and a malware scan hook (ClamAV container in docker-compose).
3. Expiring signed links resolved through an API endpoint that rechecks permission at download.
4. An export sanitizer that neutralizes cells starting with =, +, -, @, tab or carriage return.

NON-NEGOTIABLES
- No public bucket policies.
- Links never embed long-lived credentials.
- Organization scope comes from the session or API key only; permissions are enforced on the server; every mutating action writes an audit event.
- No secrets or personal data in code, fixtures, logs or messages. User-facing text exists in Arabic and English.

ACCEPTANCE (automated tests; name requirement tests test_<REQ-ID>_<behaviour>)
- Oversized or wrong-type files are rejected with a clear message.
- A link saved by a user whose access was revoked fails.
- An exported cell containing =HYPERLINK(...) is neutralized.

OUT OF SCOPE
Report generation (P9-03).

HANDOFF
Work on branch feat/p2-07-secure-file-handling-and-safe. Run make lint, make typecheck and make test. Open a PR whose description contains: summary, design decisions, a traceability table (task, PRD section, requirement id, test name), commands run with results, known limitations, and questions for the reviewer. Do not report the task as done if any acceptance test is missing, skipped or failing.
```
