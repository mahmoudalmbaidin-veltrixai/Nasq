TASK P3-02: Industry templates and coverage register
PRD: §4, §11, §28   Requirements: -   Depends on: P3-01

CONTEXT
§11: a template combines data schemas, supported constraints, default objectives, reports and configuration guidance; it cannot add an unimplemented formulation. §4: keep a coverage register per template with engine, supported constraints, exclusions, tested size range and last validation date.

BUILD
1. A template package format (YAML) and loader.
2. The first template: Batch manufacturing v1 for the production engine.
3. An engine capability manifest (provided by P4-02) and a CI check that every template constraint exists in the manifest.
4. A coverage register table with admin API and a customer-facing coverage statement export (Markdown and PDF).
5. Applying a template creates a configuration version (P3-01).

NON-NEGOTIABLES
- Industry names in templates are not claims of full support (§4).
- Organization scope comes from the session or API key only; permissions are enforced on the server; every mutating action writes an audit event.
- No secrets or personal data in code, fixtures, logs or messages. User-facing text exists in Arabic and English.

ACCEPTANCE (automated tests; name requirement tests test_<REQ-ID>_<behaviour>)
- A template referencing an unsupported constraint fails CI.
- Coverage statement export contains all five register fields.
- Applying the template creates a valid configuration version.

OUT OF SCOPE
Transportation and inventory templates (P13, P14).
