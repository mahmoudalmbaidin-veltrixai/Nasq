TASK P10-05: Production results Gantt with lock, edit and revalidation
PRD: §8, §12   Requirements: PRD01, RUN03   Depends on: P10-01, P5-06, P6-04

CONTEXT
§8 production results: line schedule, operations, conflicts and indicators; lock, edit and revalidate. §12: dragging must trigger validation before saving and prevent hard-constraint violations.

BUILD
1. A virtualized Gantt by line with filters by product and order, zoom by shift, day and week.
2. Visual distinction of setup and changeover, overtime, locked and frozen operations, and violations.
3. Drag and drop that sends the move to the edit API, shows violations, and only saves when there are no hard violations.
4. Lock and unlock controls, list view as an accessible alternative to the chart, and a reasons panel showing proven versus estimated reasons.
5. Indicators panel: utilization, changeover hours, overtime, late and unscheduled orders.
6. RTL-aware time axis decision documented (time flows left to right in both languages unless the product owner decides otherwise).

NON-NEGOTIABLES
- The browser never decides feasibility on its own.
- Organization scope comes from the session or API key only; permissions are enforced on the server; every mutating action writes an audit event.
- No secrets or personal data in code, fixtures, logs or messages. User-facing text exists in Arabic and English.

ACCEPTANCE (automated tests; name requirement tests test_<REQ-ID>_<behaviour>)
- Renders 2,000 operations smoothly (measured).
- Invalid drag is rejected with the server's message.
- Keyboard users can lock and move operations through the list view.

OUT OF SCOPE
Transportation map (P13-06).
