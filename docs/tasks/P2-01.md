## Build prompt for Claude Code

```text
You are Claude Code, acting as lead engineer on the Veltrix Operations Optimization Platform monorepo.
Before writing code, read CLAUDE.md, the PRD sections listed below in docs/prd/, docs/adr/ and docs/data-dictionary/. Restate the task in 5 to 10 bullets, list assumptions and open questions, propose a file-level plan, then write the acceptance tests first.

TASK P2-01: Shared data model and migrations
PRD: §9   Requirements: DAT03   Depends on: P0-04, P1-01

CONTEXT
§9: every record is owned by the organization, has a stable internal id and an external id when integrated, a source, modification time, active status and a version or effective date when changes affect planning. Reference data used in historical plans is deactivated, not deleted.

BUILD
1. SQLAlchemy models and migrations for: location, product (base unit, conversions, weight, volume, shelf life), order and order_line, supplier, customer, operational_resource (line, machine or vehicle with capacity and compatibility), calendar with shifts and downtime, product_routing with operations, inventory_balance and batch (available, reserved, unreleased, quality status, expiry), cost (type, value, unit, currency, effective period), execution_event.
2. A common mixin: id (UUIDv7), org_id, external_id unique per org and source, source, created_at, modified_at, active, effective_from and effective_to where planning-relevant.
3. Deactivate instead of delete, with a guard that prevents deleting rows referenced by any plan version.
4. Minimal personal data for customers and suppliers (§24).
5. An automated check comparing models with docs/data-dictionary YAML.

NON-NEGOTIABLES
- Quantities carry an explicit unit column.
- Money is Decimal with a currency code.
- Times are stored in UTC; display uses the site time zone.
- Organization scope comes from the session or API key only; permissions are enforced on the server; every mutating action writes an audit event.
- No secrets or personal data in code, fixtures, logs or messages. User-facing text exists in Arabic and English.

ACCEPTANCE (automated tests; name requirement tests test_<REQ-ID>_<behaviour>)
- Migrations upgrade and downgrade cleanly.
- Deleting a referenced product fails with a clear error.
- An effective-dated query returns the version valid at a given instant.
- The dictionary-comparison test passes.

OUT OF SCOPE
APIs (P2-02), import (P2-04).

HANDOFF
Work on branch feat/p2-01-shared-data-model-and-migrations. Run make lint, make typecheck and make test. Open a PR whose description contains: summary, design decisions, a traceability table (task, PRD section, requirement id, test name), commands run with results, known limitations, and questions for the reviewer. Do not report the task as done if any acceptance test is missing, skipped or failing.
```
