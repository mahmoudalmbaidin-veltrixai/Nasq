```text
You are Claude Code, acting as lead engineer on the Veltrix Operations Optimization Platform monorepo.
Before writing code, read CLAUDE.md, the PRD sections listed below in docs/prd/, docs/adr/ and docs/data-dictionary/. Restate the task in 5 to 10 bullets, list assumptions and open questions, propose a file-level plan, then write the acceptance tests first.

TASK P3-01: Objectives and constraints configuration
PRD: §11, §16   Requirements: CFG01   Depends on: P0-04, P2-01

CONTEXT
CFG01: results keep the rules they used. §11: users choose supported objectives; use lexicographic priorities or weights after normalization; never combine minutes, currency and quantities with unexplained default weights. Each constraint has a definition, unit, scope, source, effective date and hard or soft status.

BUILD
1. A JSON Schema per engine in packages/contracts for configuration.
2. Objective set with method lexicographic or weighted; weighted requires documented normalization factors.
3. A constraint registry: id, description, unit, scope, source, effective date, hard or soft, penalty or permitted deviation for soft constraints.
4. Immutable configuration versions with activate and roll back.
5. A validation endpoint that rejects unsupported constraint types and weighted objectives without normalization.
6. A plain-language explanation of the trade-off method for the planner.
7. Solve requests and results store the configuration version id.

NON-NEGOTIABLES
- No free-form equation editor (deferred, §32).
- Hard constraints change only through an explicit, authorized new version.
- Organization scope comes from the session or API key only; permissions are enforced on the server; every mutating action writes an audit event.
- No secrets or personal data in code, fixtures, logs or messages. User-facing text exists in Arabic and English.

ACCEPTANCE (automated tests; name requirement tests test_<REQ-ID>_<behaviour>)
- A result references the exact configuration version (test_CFG01_*).
- Weighted objective without normalization is rejected.
- Rollback restores the previous version and is audited.

OUT OF SCOPE
Templates (P3-02).

HANDOFF
Work on branch feat/p3-01-objectives-and-constraints-configuration. Run make lint, make typecheck and make test. Open a PR whose description contains: summary, design decisions, a traceability table (task, PRD section, requirement id, test name), commands run with results, known limitations, and questions for the reviewer. Do not report the task as done if any acceptance test is missing, skipped or failing.
```
