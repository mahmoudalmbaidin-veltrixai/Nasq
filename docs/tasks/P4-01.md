TASK P4-01: Solve job service
PRD: §16, §22, §23, §25   Requirements: RUN01   Depends on: P0-03, P1-03, P2-06

CONTEXT
RUN01: closing the browser does not interrupt run tracking. §25: asynchronous acceptance; per-organization concurrency, memory and time limits; concurrent operation without starvation or leakage. §22: durable jobs with cancellation and deduplication.

BUILD
1. A solve_runs table and state machine from docs/state-machines/solve.yaml.
2. Submission returns a run id immediately; the browser polls or subscribes for status.
3. Worker pool using the ADR-002 queue with per-organization concurrency caps and fair scheduling.
4. Each solve runs in a subprocess with time and memory limits (rlimit) taken from the run profile and entitlements.
5. Cancellation, heartbeats and crash recovery (requeue once, then fail with a reason).
6. Optional deduplication key (snapshot + configuration + engine) to avoid identical concurrent runs.
7. Incumbent progress updates and events for alerts.

NON-NEGOTIABLES
- A crashed or canceled run never publishes a plan.
- Every run stores actor, org, snapshot and configuration ids.
- Organization scope comes from the session or API key only; permissions are enforced on the server; every mutating action writes an audit event.
- No secrets or personal data in code, fixtures, logs or messages. User-facing text exists in Arabic and English.

ACCEPTANCE (automated tests; name requirement tests test_<REQ-ID>_<behaviour>)
- Closing the client does not affect the run (test_RUN01_*).
- Fairness: organization A submits 20 runs; organization B's single run starts within the configured wait.
- Killing a worker marks the run failed or retried by policy.
- Cancel takes effect within 2 seconds.

OUT OF SCOPE
Engine logic (P5).

HANDOFF
Work on branch feat/p4-01-solve-job-service. Run make lint, make typecheck and make test. Open a PR whose description contains: summary, design decisions, a traceability table (task, PRD section, requirement id, test name), commands run with results, known limitations, and questions for the reviewer. Do not report the task as done if any acceptance test is missing, skipped or failing.
