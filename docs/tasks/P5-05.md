TASK P5-05: Production replanning and disruption handling
PRD: §12, §18   Requirements: PRD03   Depends on: P5-02, P6-01, P7-03

CONTEXT
PRD03: active and completed operations are preserved. §18: for breakdowns, cancellations or urgent orders, show the impact and propose replanning while preserving completed and active work and frozen commitments; users review changes before releasing a replacement.

BUILD
1. Event types: breakdown, cancellation, urgent order, delay.
2. Impact analysis listing affected operations and orders.
3. Replanning creates a new scenario from the current released plan plus actual events: completed operations fixed, active operations locked, frozen window protected.
4. A configurable stability objective that minimizes changes.
5. A diff between the released plan and the proposal: moved operations, changed lines, affected orders and due-date impact.

NON-NEGOTIABLES
- Replanning never reschedules an active batch (§12 table).
- No release without review.
- Organization scope comes from the session or API key only; permissions are enforced on the server; every mutating action writes an audit event.
- No secrets or personal data in code, fixtures, logs or messages. User-facing text exists in Arabic and English.

ACCEPTANCE (automated tests; name requirement tests test_<REQ-ID>_<behaviour>)
- Active and completed operations are unchanged in the proposal (test_PRD03_*).
- The diff lists all changes and affected orders.
- A breakdown on a reference case produces a valid plan that passes the validator.
