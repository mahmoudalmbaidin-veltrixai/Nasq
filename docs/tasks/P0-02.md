## Build prompt for Codex

```text
You are Codex, acting as implementation engineer on the Veltrix Operations Optimization Platform monorepo.
Before writing code, read AGENTS.md, the PRD sections listed below in docs/prd/, docs/adr/ and docs/data-dictionary/. Restate the task in 5 to 10 bullets, list assumptions and open questions, propose a file-level plan, then write the acceptance tests first.

TASK P0-02: CI pipeline and quality gates
PRD: §27, §29   Requirements: -   Depends on: P0-01

CONTEXT
Both agents open PRs. Every PR must pass the same automated gates so quality does not depend on which agent wrote the code.

BUILD
1. GitHub Actions workflow on pull_request: ruff, eslint, mypy, vue-tsc, pytest with coverage (fail when coverage of changed lines in apps/ and packages/ is below 80%), Vitest.
2. Migration job: start an empty Postgres, run alembic upgrade head, downgrade base, upgrade head again.
3. OpenAPI job: generate the schema, diff it against main and post the diff as a PR comment; fail on breaking changes unless the PR has the label api-breaking.
4. Security jobs: gitleaks, pip-audit, npm audit (fail on high), license allowlist check.
5. import-linter job enforcing: packages/validators must not import packages/engines; apps/web never imports server code.
6. Playwright smoke job (placeholder test) and Docker image build for api, worker and web.
7. Nightly workflow placeholder for `make bench` that uploads benchmark artifacts.
8. Document the required status checks in docs/runbooks/ci.md.

NON-NEGOTIABLES
- Workflows use `permissions:` with the minimum needed.
- No deployment secrets in this repository.
- Every failing gate must block merge.
- Organization scope comes from the session or API key only; permissions are enforced on the server; every mutating action writes an audit event.
- No secrets or personal data in code, fixtures, logs or messages. User-facing text exists in Arabic and English.

ACCEPTANCE (automated tests; name requirement tests test_<REQ-ID>_<behaviour>)
- A test branch with a lint error, a type error, a failing test, a fake secret and a forbidden import is blocked by the matching job (attach screenshots or logs).
- Migration up/down/up runs on every PR.
- OpenAPI diff is posted.
- Full CI on the scaffold finishes in under 15 minutes.

OUT OF SCOPE
Production deployment (P11-05).

HANDOFF
Work on branch feat/p0-02-ci-pipeline-and-quality-gates. Run make lint, make typecheck and make test. Open a PR whose description contains: summary, design decisions, a traceability table (task, PRD section, requirement id, test name), commands run with results, known limitations, and questions for the reviewer. Do not report the task as done if any acceptance test is missing, skipped or failing.
```

## Review prompt for Claude Code

```text
You are Claude Code, reviewing the pull request for TASK P0-02: CI pipeline and quality gates. Codex wrote this code; you did not. Review it independently.
1. Read docs/tasks/P0-02.md, PRD §27, §29 and the full diff.
2. Check that every acceptance criterion has a test that would fail if the behaviour broke. Run make test and the task's tests yourself.
3. Focus for this task: Every gate actually blocks merge, least-privilege workflow permissions, no credentials, reasonable run time.
4. Always check: organization isolation (add a cross-tenant test if one is missing), server-side authorization, audit events, idempotency, reversible migrations, Arabic and English strings, actionable errors, no secrets or personal data, no unlabeled mock data, no import from engines into validators.
5. Reply with: verdict (approve or request changes); blocking issues with file:line, why it matters (cite the PRD) and a concrete fix; non-blocking suggestions; missing tests (write small ones directly). Do not rewrite the feature.
```
